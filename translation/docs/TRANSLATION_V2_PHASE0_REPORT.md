# تقرير Phase 0: إصلاحات سلامة النتائج والتشغيل

**التاريخ:** 2026-11-25 · **الفرع:** `translation-v2-language` (محلي، غير مرفوع) · **النطاق:** P0-1 إلى P0-5، والبنود المرفوعة A وB وC وD، وجزء `degraded` من P1-7.

**القيود التي التُزم بها:**
- لا تشغيل لأي نموذج، ولا Colab ولا Kaggle ولا GPU، ولا استدعاء لأي API.
- لا حذف لنتائج أو ملفات أصلية، ولا تغيير لمعرّفات المصدر أو توقيتاته.
- لا دمج في `main`، ولا رفع إلى GitHub، ولا تعديل على FigJam.

**طريقة العمل لكل إصلاح:**
1. اختبار يفشل أولًا.
2. أصغر إصلاح.
3. نجاح الاختبار.
4. كل الاختبارات.
5. commit منفصل.

### P0-2 — فشل الـ API والكاش و`degraded` (`9b5d269`)
- **السبب الجذري:** `chat_json` كان يعيد `None` بعد 5 محاولات فاشلة، فيُكتب `items: []` في كاش يُكتب مرة واحدة، ولا يُعاد أبدًا.
- **الإصلاح:**
  - **ثلاثة أنواع فشل:**
    - `TransientLLMError`: الخدمة لم تجب. **لا يُخزَّن**، والوحدة «مؤجلة».
    - `PermanentLLMError`: الطلب مرفوض. يُخزَّن مرة واحدة بحالة `error`، ولا يُعاد بلا نهاية.
    - `None`: النموذج أجاب بلا JSON صالح. نتيجة فارغة حقيقية بحالة `empty`.
  - **منع التكرار غير المحدود:** محاولات محدودة داخل العميل، وبعد 3 تأجيلات متتالية يتوقف المولّد لهذا التشغيل.
  - **كل أدوار الـ LLM** (القاموس، والتصحيح، والترتيب، والتحرير) تتوقف عند أي فشل بدل الانهيار أو الاستمرار الصامت.
  - **`degraded`:**
    - يُحسب من الأدوار المتوقفة، والوحدات المؤجلة والمرفوضة، والكاش القديم، والقاموس غير المبني.
    - يُسجَّل في الـ manifest (الذي صار يُكتب في النهاية، مع `run_started.json` في البداية)، وفي metrics وregistry.
    - `compare_v1_v2` يرفض التشغيل المنقوص.
  - **`benchmark.generate_cached`:** لا يكتب الفشل المؤقت.
- **الملفات:** `generators.py`، `pipeline.py`، `benchmark.py`، `colab.py`.
