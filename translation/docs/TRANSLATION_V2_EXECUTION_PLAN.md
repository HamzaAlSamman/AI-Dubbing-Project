## القرارات المعتمدة (2026-11-25)
- **المعمارية:** الإبقاء على عدة ترجمات بالتوازي ثم الاختيار. لا نماذج أو وكلاء جدد قبل إثبات الحاجة.
- **المخاطبة:** المفرد افتراضيًا، قابل للتغيير، مع احترام سياق المصدر.
- **اللغة:** فصحى مبسّطة طبيعية مناسبة للإلقاء التعليمي.
- **Gemini:** يبقى الآن. خيار مستقل ومحلي يُدرس لاحقًا.
- **Fine-tuning:** لا في المرحلة الحالية.
- **دبلجة آلية بالكامل:**
  - لا مراجعة بشرية إلزامية.
  - المصطلحات غير المؤكدة اقتراحات لا أسباب رفض.
  - التقييم البشري العلمي خارج الـ pipeline.

**طريقة العمل لكل مهمة:**
1. اختبار يفشل أولًا.
2. أصغر إصلاح صحيح.
3. نجاح الاختبار.
4. كل الاختبارات السابقة.
5. مراجعة الآثار.
6. commit منفصل.

### حارس المعنى — تخطيط فقط (لم يُنفَّذ)

**ما لا نفعله:**
- لا نجعل مطابقة الكلمات بين `accurate_ar` ونص الدبلجة شرطًا قطعيًا.
- لا نعتمد الترجمة العكسية ضمانًا للمعنى.
- لا نعتبر `accurate_ar` مرجعًا معصومًا.
- لا نثبّت مولّدًا للترجمة الدقيقة قبل تقييمه.

**التصميم المقترح للمقارنة:**
1. **مجموعة اختبار للحارس** (من بيانات التطوير)، تحتوي:
   - (أ) إعادات صياغة صحيحة: نفس المعنى، كلمات مختلفة، تقسيم جمل.
   - (ب) أخطاء مزروعة: إضافة جملة، وحذف متغير أو صفة، وحذف نفي، وتغيير رقم، وتغيير مصطلح.
   - (ج) حالات حقيقية من التطوير: `tu_0040` (إضافة)، و`tu_0032` (معنى مخترع)، و`tu_0024` (حذف صفة). هذه **regression cases ضمن التطوير**، لا بيانات اختبار مستقل، وتبقى محلية لأن نص المحاضرة خاص.
2. **الطرق المقارنة:**
   - حفظ الأرقام والرموز والنفي.
   - حفظ المفاهيم (المصطلحات والمتغيرات وصفاتها).
   - MetricX-QE بفارق سماح.
   - تقييم دلالي بنموذج من عائلة أخرى.
   - مزيج منها.
3. **المقياس:**
   - recall للأخطاء المزروعة: كم خطأ يلتقط.
   - **false rejection** على إعادات الصياغة الصحيحة: كم ترجمة صحيحة يرفض. هذا مهم لنظام آلي بالكامل.
4. **القرار:** الطريقة ذات أفضل توازن، بحد أقصى مقبول للرفض الخاطئ يُحدَّد مسبقًا.
